## スキル作成ルール

$ARGUMENTS の内容に基づいて新しいスキルを作成してください。

### 必須フォーマット

スキルは以下の構造で作成する（**これ以外は認識されない**）:

```
.claude/skills/<スキル名>/SKILL.md
```

**絶対に `.claude/commands/*.md` に作らないこと。** これはレガシー形式で `/skills` に表示されない。

### SKILL.md テンプレート

```yaml
---
name: <スキル名（小文字、ハイフン区切り、英数字のみ、64文字以内）>
description: <何をするスキルか + いつ使うか（Claudeが自動判定に使う）>
---

<スキルの本文（プロンプト）>
```

### フロントマターの任意フィールド

| フィールド | 用途 | 例 |
|-----------|------|-----|
| `argument-hint` | 引数のヒント表示 | `[issue番号]` |
| `disable-model-invocation: true` | 手動実行のみ（自動起動しない） | デプロイ系など危険な操作 |
| `allowed-tools` | 許可するツール | `Bash(git *), Bash(npm *)` |

### 本文のベストプラクティス

1. **目的を明確に** — 最初の1行でこのスキルが何をするか書く
2. **手順をステップで** — 番号付きリストで実行順序を明示
3. **`$ARGUMENTS`** — ユーザーの引数を参照する変数。適切に使う
4. **出力形式を指定** — 結果をどう表示するか明記する
5. **MCP使用時** — どのMCPを使うか明記する（例: 「SQLite MCPを使って」）
6. **注意事項** — 破壊的操作がある場合は確認ステップを入れる

### 作成後

1. スキルファイルを書き込む
2. gitにaddしてコミットする（ユーザーに確認してから）
3. 「Claude Code再起動で `/スキル名` として使えるようになる」と伝える
