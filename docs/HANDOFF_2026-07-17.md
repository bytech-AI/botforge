- 日付境界を UTC 固定から `Asia/Tokyo` 基準へ統一。
- `BOTFORGE_TIME_ZONE` でIANAタイムゾーンを変更可能にした。

- CP/RP、送金上限、AI採点日次上限、cronロック、シーズン処理にも同じ日付修正を適用。

## ホスティング調査

### Vercel

BotForge 全体をそのままVercelへ移すことはできない。

- Bot本体はDiscord Gatewayへ常時WebSocket接続し、heartbeatを継続する常駐プロセス。
- Vercel Functionsはリクエスト単位で終了し、Hobbyでは最大実行時間があるため24時間のBotプロセスを維持できない。
- SQLite DBと暗号化キー等のローカルファイル保存も、Vercelの一時ファイル環境では維持できない。
- Vercelへ移せるのは主にReact管理画面。Bot本体用の常駐サーバーと外部DBが別途必要になるため、現時点では分割移行を推奨しない。

### 課金ゼロでの推奨順

1. このPCまたは余っているPCでBotForgeを常時起動する。最短で、SQLiteもそのまま利用可能。
2. クラウド必須なら Oracle Cloud Always Free VM を検討する。Dockerと永続ディスクを使えるが、登録・初期設定・空き容量問題がある。
3. Northflank Sandbox は料金表上 always-on/no sleeping の無料サービスがある。ただしコンテナ内SQLiteの永続性が問題になるため、無料PostgreSQL等へのDB移行が必要。
4. Render/Koyebの無料枠はスリープまたはscale-to-zeroがあり、Discord Botの常時運転には不向き。

## セキュリティ上の注意

- 現在の管理画面/APIには、インターネット公開に十分な管理者認証がない。
- `requireBotConnected` は認証・認可ではない。
- 自宅PCで運用する場合、管理画面をそのままポート開放しない。localhostまたはVPN内だけで使う。
- 外部公開するなら、先に管理者ログイン、セッション、CSRF対策、API認可、秘密情報管理を実装する。

## 再起動後に行う候補

最短復旧方針は「このWindows PCで常駐運転」。次のターンで以下を確認・実施する。

1. ローカルの `data/botforge.db` と暗号化キー／環境変数が揃っているか確認する（秘密値は画面やログへ出さない）。
2. `npm.cmd test` と `npm.cmd run build` を再実行する。
3. Botをローカル起動し、Discord接続、`/daily` 登録、受取、二重受取拒否を実環境で確認する。
4. Windows再起動後も自動起動するよう、タスクスケジューラまたはサービス化を行う。
5. 管理画面はlocalhost/VPN限定にする。

クラウド運用を選ぶ場合は「OCI Always FreeへDocker移行」を次候補とする。Vercel単独移行は選ばない。
